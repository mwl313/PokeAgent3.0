# Snapshot closure audit

Read-only audit, 2026-10-07. Sources are current `engine/src/state.rs`, `battle.rs`, `battle/hooks.rs` and pinned Showdown commit `14546894d86f9589ac11130c510bbe73b6968665`. No Rust changes are made by this note. Snapshot integrity hashes detect accidental corruption; they are not authentication, and re-signed payloads still require structural checks.

## Concrete current weaknesses

1. **Major-status numeric payloads are not bounded.** Restore only requires a nonempty values vector for sleep, freeze and toxic (`state.rs:566` vicinity). Supported sleep/freeze execution decrements values[0] (`battle.rs:1213`); toxic adds one (`1767`). A re-signed payload containing i64::MIN for sleep/freeze or i64::MAX for toxic can overflow in debug builds, and arbitrary values produce incorrect timers in release builds. Require exactly the supported payload shape and boundary range: sleep remaining 1..3; freeze remaining 1..3; toxic stage 0..15. Determine valid ended/operational snapshot exceptions from privileged boundary fixtures, rather than admitting arbitrary counters. Burn/paralysis/ordinary poison require empty values. Typed status state ID must correspond to supported statuses; generic condition IDs are not valid major statuses. Preserve original retained status state on fainted native status-marker normalization where the reference does so.

2. **Protect stall payload is unchecked.** Existing restore accepts a stall with arbitrary values/duration. Protect casts values[0] to u32 and calls chance(1, counter); counter 0 (or a large i64 whose low 32 bits are zero) violates BattleRng's positive-denominator assertion (`battle.rs:882`, `rng.rs:chance`). Counter multiplication can also overflow (`battle.rs:911`). Require exactly one counter in {3,9,27,81,243,729}, supported duration 1..2, and active/live lifecycle consistent with clear_volatile. Protect itself has duration 1 and empty values; flinch duration 1 and empty values. Missing durations on Protect/flinch currently cause those effects to persist incorrectly rather than naturally expire. Choice lock needs one valid move ID belonging to the recorded request/move repertoire, no duration, and valid lifecycle. A blanket ID-in-catalogue check does not validate these shapes.

3. **Turn counters are unchecked.** Re-signed turn=65535 or active_turns=65535 can overflow on native end_turn increments (`battle.rs:1869–1872`). Restore should validate reachable preview/normal/end boundary ranges under the pinned 1000-turn rule, and active_turns relative to the battle's elapsed turns. Operational snapshots may contain a partial transition; explicitly distinguish such states instead of inventing a normal playable phase. Tests must check both rejection and the final legal turn-limit boundary.

4. **Condition context is not closed.** Generic valid_effect checks only condition catalogue membership and source roster; an arbitrary registered condition can be stored in Pokémon volatiles or side/slot/field maps. Unsupported timed volatiles are then treated as generic duration entries and removed; unknown untimed ones can silently persist. Restrict accepted condition IDs/shapes to currently implemented location-specific effects, or reject unsupported state explicitly. Weather, terrain and room durations/sources and Flash Fire shape already have focused checks; extend those checks to all currently supported statuses/volatiles. Do not narrow the legal training team corpus to work around this. The engine's unsupported guard must remain explicit for future unported effects.

5. **Request/queue/outcome phase consistency is only partially validated.** request.validate and pending validate_joint are useful, but do not prove requests match the actual selected/active roster, PP, Mega availability and battle outcome. Queue validation checks numeric IDs and some fields but does not certify every kind-specific actor/destination/payload relationship. Finished versus preview/normal/replacement, pending actions, mid_turn and terminal reasons need a documented boundary contract. Do not accept a re-signed terminal outcome with a normal request and later execute it as a normal battle. Add decisive corruption cases per supported request phase, not tests mirroring every implementation statement.

Legal/catalogue checks are distinct: restore currently checks species/ability/item/type IDs, not whether an arbitrary altered world is a reachable legal M-C state. Full replay provenance is one possible stronger contract; recomputing initial team legality cannot by itself validate Mega/status/switch runtime changes. Define the intended trust boundary before enforcing reconstruction. Do not prohibit future dynamic forms merely because they differ from initial sets.

## Effect order: implemented guarantees and remaining tests

Schema 4 has `next_effect_order:u32`, private optional ability/item orders, and generic order plus assigned flag. Assigned zero is legitimate because the reference counter starts zero. None/unassigned zero is separately represented. Restore validates assigned ranges and uniqueness, keeps inactive historical assignments, rejects active nonempty ability/item states without assignment and prevents field assignment for current nonallocating field constructors. These are real improvements; no further schema change is justified solely by this audit.

Current allocator checked_add returns an explicit operational error at counter exhaustion; it never wraps or consumes RNG. A payload with next_effect_order=u32::MAX can pass range checks and fail on next accepted creation. That is not a native success/draw. Add a direct regression for exhaustion and ensure downstream batching/reward paths preserve operational failure. Because creation can fail after an incoming Pokémon becomes active, the resulting operational world may not satisfy normal playable-state invariants. Decide whether failed worlds remain snapshot/exportable, and either validate that explicit operational shape or make creation reservation transactional. Do not silently increment after a failed allocation, label exhaustion as a natural battle end, or treat u32::MAX as proof of a legitimate reachable history.

Raw global equality is stronger than relative order. Current reference-counter tests compare actual orders, not just redirects, across accepted creations. Extend them to all new Flash Fire/Lightning Rod fixtures, invalid status attempts, repeat volatile activation, item consumption, and reentry. Counter holes are legal; no requirement for contiguous retained orders. Runtime snapshot phases may retain a status state after the public faint marker replaces status. Field states are nonallocating because reference constructors omit target (`sim/field.ts:70`,141,200); Side constructors explicitly include target (`sim/side.ts:426`,478). Never add global order as a tie breaker to ordinary events: Showdown attaches it only for SwitchIn/RedirectTarget (`sim/battle.ts:997–1003`).

## Action-local state for future type conversion

Current Weather Ball uses a move clone local to one action; Flash Fire changes the shared action accuracy sentinel before all surviving targets' accuracy checks. Keep shared Dex immutable. Snapshot/replay at submission boundaries does not currently expose in-flight local moves; future resumable mid-action callbacks require serializing an explicit active action state before allowing snapshots at those points.

Future Normalize, Pixilate/Aerilate/Refrigerate/Galvanize, Electrify/Ion Deluge, Liquid Voice, terrain-sensitive moves, Protean/Libero, Transform and called moves require ordered action-local type/category/power/accuracy/flags/target/secondary state. Export missing cold flags and dynamic-effect IDs; do not infer conversion only from original Dex type. Resolve the converted move before RedirectTarget, then preserve that same local state through absorption, immunity, STAB, weather, terrain, critical/damage modifiers and post-hit callbacks. Redirection bypass metadata, original type versus converted type conditions, and mutation by any spread recipient need separate reference cases.

These future handlers are not implemented by adding snapshot fields alone. Keep them operationally unsupported until their complete reachable interactions and boundary requirements are ported. A generic JSON blob or cloned entire environment in the hot path would not satisfy the native architecture.
