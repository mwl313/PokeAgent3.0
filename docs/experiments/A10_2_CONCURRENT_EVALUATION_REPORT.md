## Actual execution and performance

The previous sequential reference was 1.23 games/sec. CPU batch sweeps measured 3.11 (batch 8), 3.40 (16), 3.32 (32), 2.91 (64), and 3.29 (128) games/sec with two PyTorch threads and two native workers. Panel sizes varied between 64 and 256 games, so these are short tuning observations. A separate 256-game batch-16 run measured **3.268 games/sec / 78.331 seconds**, peak RSS **658,268 KiB**, on affinity **16–19**. This is 2.66× the historical sequential reference, not a controlled same-backend speedup claim. Batch 32 with one PyTorch thread measured 1.863 games/sec and reduces contention. Batched model execution consumed 76.75 of 77.89 seconds in the batch-128 trial; candidate conversion consumed 0.056 seconds. Sampling/conversion refactoring is therefore not warranted by this profile.

PPO's eight preceding completed iterations averaged **90.394 games/sec**. The seven complete iterations inside the broad tuning window (71–77) averaged **87.548 games/sec**, a **3.149% decrease**. This is a live observational comparison; model-dependent battle lengths and ordinary variation confound causal attribution. The isolated batch-128 interval included only one full PPO iteration (87.149 games/sec, −3.590%). The single-thread interval included two full iterations (91.327 games/sec, +1.031%). During the initial automatic jobs, a later rolling five-iteration reading fell to 85.870 games/sec (−5.005%), and the worker automatically reduced to one thread/one native worker. It remains automatic rather than stopping the league. Above 20% observed degradation it defers evaluation for 30 seconds and rechecks; this heuristic can also react to ordinary PPO variability.

Both PPO processes remained present and advanced throughout. NVIDIA compute ownership showed only the two PPO workers; CUDA is hidden from the evaluator. Per-core `/proc/stat`, CPU/memory/I/O pressure, RAM and GPU samples are retained in `evaluation/league_v2/resource_samples.json`. RAM available was approximately 47.9 GiB, memory pressure was zero during those samples, and the evaluator's pages were predominantly on NUMA 0 (631 MiB on node 0 versus 37 MiB on node 1). Hardware memory-bandwidth counters were unavailable and are not estimated.

## Fixed defects and operational semantics

- Discovery pins one generation name and opens both rank files before reading. Concurrent `LATEST` replacement cannot mix models; opened descriptors remain readable after unlink by rotation. SHA, clock, DDP, schema, architecture, precision, source and dataset checks fail closed.
- Inference archives contain model weights/metadata, no optimizer or training RNG. Files and metadata are atomically published, content-addressed, and verified before use. Existing historical archives and PPO generation directories remain untouched.
- Cache uses the A7/A8 evaluation identity including both policy hashes/model digests, fixtures, seed, environment hashes, actual native binary, execution/sampling semantics, batch/thread/worker settings and evaluator code digest. Repeating the 256-game request returned a cache hit; changed seeds/configurations use distinct identities.
- Jobs bind actual immutable policy IDs and true clocks. Old milestone jobs are not consumed. `milestones.json` records absent exact 50k snapshots; it never assigns a newer model to them.
- The worker uses 256 → 1,024 → 2,048 games, disjoint extensions of a frozen 1,024-pair panel. Completed chunks are cached, running jobs survive restart, retries are bounded to three, and the future backlog retains the newest four relevant candidates. Compact receipts are retained.
- Promotion requires direct paired outcomes against the current incumbent. Pair-cluster Hoeffding bounds spend alpha across outcome-independent candidate/opponent ordinals and three predefined stages: `0.05 / [a(a+1)b(b+1)3]`. The total over all pairs/stages is ≤0.05 by a union bound, so fixed-panel reuse/adaptive incumbent selection does not justify uncorrected repeated 95% tests. Bootstrap CIs are descriptive; promotion uses the conservative bound. Inconclusive results retain the incumbent after the final stage.
- The canonical pointer is `evaluation/league_v2/best_policy.json`; previous pointers/promotions and evidence receipts are preserved atomically. `BestPolicyHandle.refresh()` verifies and loads a replacement between inference requests; actual reload and no-op repeated refresh were exercised. No running inference consumer existed to hot-reload, and PPO never consumes this pointer.
- Evaluation-only archive budget is 2 GiB, with first two snapshots, recent eight, best/recent bests and pending job dependencies protected. Only owned `league_v2/policies/*.pt` files are eligible for cleanup. Discovery/worker preserve ≥20 GiB headroom, above the production 15 GiB reserve.

## Services

`a10-evaluation.timer` discovers checkpoints every ten minutes. `a10-evaluation-worker.service` is a separate persistent battle worker with auto-restart, CPU affinity 16–19, Nice 10, idle I/O, no CUDA visibility, CPUQuota 400%, MemoryHigh 2 GiB and MemoryMax 3 GiB. CPUQuota 25% was removed from the battle execution path. The lightweight discovery unit uses CPUQuota 100%. Neither unit depends on or manages PPO. The old queue-only scheduler timer is disabled.

Focused regression tests passed (20 tests), real smoke/tuning/256-game matches completed, cache reuse was exercised, automatic job consumption and promotion were observed, and the status command reports actual active stage progress. PPO, Rust mechanics, frozen teams, optimizer, checkpoint cadence and source provenance were not modified.
