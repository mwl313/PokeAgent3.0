# PokeAgent3.0 — 훈련 방식 리서치 & 제안 (WORKING DRAFT v0, 2026-10-09)

> 상태: 초안 골격. §0/§1/§5/§6은 확정 수치 기반으로 작성됨. §2-§4는 리서치(서브에이전트 2기 + 자체 분석) 통합 대기 중.

## §0 목적과 전제

- 목표: "가장 효율적이고 강력한 모델" — 벽시계 시간과 전기/기기 수명 대비 최대의 실력.
- 사용자 판단(2026-10-09): **100M 자연경기 목표는 비현실적** (현 스피드 32.5 games/s → 35.6일 상시 가동 + 전기 + 기회비용). 스펙(Full Spec 1.1)의 계약에 얽매이지 않고 재설계 가능.
- 변경 허용: 학습 알고리즘, 데이터 재사용, 오프폴리시, 지도학습(인간데이터), 리그/상대 스케줄, 서치, 모델 아키텍처, 평가 방식.
- 하드웨어 고정: 미니DC (2×V100 32GB, fp16, P2P 없음, GPU 전력 175/150W, 64GB RAM). 클라우드 Auto-rental은 스펙상 금지(해제는 사용자 결정 사항).

## §0.5 경쟁 구도와 차별화 목표 (사용자 명시, 2026-10-09 추가)

- 벤치마크 대상: **Jaxcalibur**(randbats 계열)과 **mikumiku37**(M-C 래더 #1, 8.7M 파라미터, RTX 5090 48h, 턴 단위 내시 서치) — 최근 가장 핫한 최상위 로컬 RL 봇들. 둘 다 핵심 자산 비공개(가중치/하네스).
- 목표: 그들보다 **강한 모델**, 또는 **유의미한 강점으로 차별화된 모델**. "같은 축(더 많은 RL·더 많은 게임)에서 숫자 승부"는 불가 — 상대는 이미 대량 RL을 완료했고 컴퓨트도 우위(5090 등).
- 함의(전략 재조정): 우리의 승부처 후보 =
  1. **샘플 효율** (같은 벽시계에 더 나은 학습: BC 워밍스타트 + 오프폴리시 재사용)
  2. **추론 서치** (우리 Rust 엔진의 충실도·속도로 더 깊은/정확한 탐색 — miku 경로의 강화판)
  3. **상대 모델링/정보 처리** (불완전정보·팀 프리뷰·set priors: 인간 메타 통계 활용)
  4. **팀 선택·팀 운용** (VGC 실력의 절반 — 팀풀 기반 선택 정책은 대부분 봇이 고정팀)
  5. **인간 데이터 자산** (614K 리플레이 → 사전확률/워밍스타트/증류)
- §4 옵션 평가 가중치를 "정면 승부 회피 → 차별화 축 우선"으로 재정렬할 것.

## §1 현재 스택 감사 (실측/설정 기준)

### 1.1 처리량 (2026-10-09 실측)
- all-in 32.50 games/s (듀얼, micro 1024, 2,048경기 이터레이션: 수집 12.4s + 업데이트 42.2s).
- 분해: 업데이트가 긴 폴(77%), GPU 95%+ 점유. 수집은 23%.
- **엔진 단독 스루풋은 2,579-2,689 games/s** — 즉 학습 루프(정책 추론 + PPO + 데이터 변환)가 엔진 대비 약 80x 병목. "게임 수"를 늘리는 것보다 "게임당 학습 효율"이 지배적.

### 1.2 현재 학습 설정 (configs/train.yaml 발췌)
- 알고리즘: PPO (on-policy). **ppo_epochs: 4**, clip 0.2, lr 3e-4 (warmup 25만 경기 → cosine → 3e-5 @ 100M), gamma=1.0, GAE λ 0.95, entropy 0.01, target_KL 0.03.
- 계약: 이터레이션마다 정책 동결(수집) → 업데이트 1회. 최소 131,072 결정(약 4,965경기)/이터레이션.
- 상대: current 50% + historical 50% (최대 8개 스냅샷, 100만 경기(=약 8.5시간)마다 1개).
- 평가: 100만 경기마다 512판 (승격 게이트). → **학습 곡선을 알 수 없는 설계** (하루 1회 미만 피드백).
- 보상: 승 +1 / 패 -1 / 무 0. 셰이핑 없음.
- 모델: PA3-8M (트랜스포머 6층 d320 + GRU 프리픽스 디코더, 4 브랜치 × 64 후보).
- 스펙에서 명시적으로 꺼둔 레버: `human_action_bc: false`, `train_search: false`, `external_llm_in_battle_loop: false`, `model_architecture_sweep: false`, `small_team_curriculum: false`.

### 1.3 "100M이 필요하다"는 가정의 검증 부재
- 100M은 벤치가 아니라 임의 목표. **Elo-경기수 곡선 데이터가 아직 없음.**
- 따라서 첫 질문은 "100M을 어떻게 채우나"가 아니라 **"강함은 경기수에 대해 어떤 곡선을 그리나"**.
- 권고: 저비용 파일럿 학습 런(수백만 경기) + 촘촘한 평가로 곡선 측정 → 외삽으로 목표 규모 결정.

### 1.4 시간/비용 산정 (개략, 가정 명시)
- 100M 경기 @32.5/s = 3,077시간 = **35.6일 상시 가동**.
- 전력: 풀부하 약 0.55-0.65kW 가정 → 약 470-550 kWh → 한국 가정용 ₩8-15만 수준(추정, 계절/누진 요금에 따라 상이). 전기료보다 **35일간 기기 점유(다른 작업 불가) + 열/수명 부담 + 검증 리스크**가 실질 비용.
- 대안 기준: 같은 35일에 하이브리드 설계(BC 워밍스타트 + 저활용률 개선)라면 등가 진전이 훨씬 클 수 있음(§4에서 정량화 예정).

### 1.5 재사용 가능한 데이터 자산 (로컬 확인, 2026-10-09)
- `~/Projects/MWL-PokeAgent/data` **7.3GB**: `replays/` 2.6G(원본+parquet+평점 필터본) / `processed/` 1.5G — 구 Laya 트랙에서 **파싱·정제 완료된 결정 데이터셋**(`laya_all.jsonl.gz` 330M, `laya_mc`, `laya_v3/v4` 평점 버킷 b1200/a1300/s1400 등, M-C 포함) / `artifacts/` 3.1G.
- 함의: 옵션 A(BC 워밍스타트)의 **변환 기반이 이미 상당 부분 존재** — PA3 관측/행동 스키마로의 재변환이 필요하나 제로에서 시작하는 것이 아님. 평점 필터/사용자 지침(저평점 데이터 제외) 재확인 필요.

## §4 옵션 패키지 [초안 — 자체 분석, 수치 보강 대기]

각 옵션: 내용 / 이득 가설 / 비용·공수 / 리스크.

- **P0. 측정 우선 (필수 선행)**: 평가 스파인(§5) 구축 + 현 파이프라인 파일럿 런(2-5M 경기 = 0.7-1.8일)으로 **Elo-경기수 곡선** 확보. 이득: 모든 비교의 기준선, "100M이 필요한지"를 데이터로 판정. 비용: 에이전트 수일 + GPU 며칠. 리스크 낮음. ※ 현 설계는 100만 경기당 1회 평가라 곡선이 안 나옴 → 평가 주기 재설계가 P0에 포함.
- **A. 인간 리플레이 워밍스타트 (BC) + 현 PPO 지속**: 614K 리플레이(로컬 7.3GB 자산)를 PA3 스키마 (obs, action, mask)로 변환, 지도학습 사전학습 후 SP PPO 초기화로 투입. 이득 가설: "무작위에서 멍청함을 벗어나기까지" 구간을 건너뜀 — 자체 선례(Laya 트랙: 50K BC로 vs random 64→88%)와 AlphaStar 관행. 비용: 변환기+학습 스크립트(수일). 리스크: 포맷 미스매치(관측 스키마/행동 공간, M-C 더블스 폐쇄시트와 수집분 정합) 실측 필요.
- **B. 오프폴리시 재사용 루프 (V-trace + 리플레이, 지연 허용)**: 수집/학습 분리 + 리플레이 버퍼 + bounded staleness + V-trace 보정. 2-GPU에서 겹침 이득은 제한적이나 **재사용률 상승이 핵심**(샘플당 갱신 횟수 ×5-10 가설). 비용: 구현 큼(버퍼·스테일니스·보정·검증 재설계). 리스크: 소규모 오프폴리시 불안정 — KL/스테일니스 가드 필요.
- **C. 리그/PFSP 강화**: 스냅샷 8개·100만 경기 간격 → PFSP(승률 가중 상대 샘플링) + exploiter 트랙. 비용 소, 독립 적용 가능. 잊음/순환 방지.
- **D. 서치 증강 (턴 단위 내시해, miku 스타일)**: Rust 엔진 + 후보 가지치기로 턴마다 소규모 동시수 해법, 정책 사전확률 결합. 용도: 평가 상한 / 교사 타깃 증류. 이득: miku가 실증한 경로(48h·5090·래더 1위). 비용·난이도 최상. 후순위.
- **E. 클라우드 버스트 (참고)**: 스펙상 금지 상태. 재고 시 4090/5090 임대로 단기 ×3-5 처리량. 상시비용·데이터 이동·격리 이슈. 사용자 결정 사항으로만 기록.

**권고 스테이징(가설)**: P0 즉시 → A·B를 소규모 파일럿 A/B로 비교 → 승자 + C 결합으로 본학습 → D는 상한 작업으로 별도. 목표도 "N경기"가 아니라 **"D일 내 X Elo"** 형태로 재정의.

## §5 평가·검증 재설계 [확정 초안]

알고리즘을 바꾸면 기존 검증(다이제스트 등가성 게이트)은 적용 불가 — **평가 기반 검증**으로 전환 필요:
1. **고정 상대 배터리** (변하지 않는 기준): random, 휴리스틱, 초기·최고 체크포인트, (가능하면) 공개 봇. 각 N판 승률 + Elo 추정.
2. **Elo/TrueSkill 시스템**: 체크포인트 간 상대전으로 내부 Elo 레이더 운영 (평가 비용: 1M경기당 512판은 불충분 → 상시 레이더로).
3. **학습 곡선 대시보드**: 경기수 vs Elo를 매 구간 기록 — 의사결정의 단일 근거.
4. **회귀 안전장치**: "베이스 상대 승률이 일정 이하로 떨어지면 플래그" (자기대전 망각/순환 감지).
5. 정확성 규율(재현성, 원본 JSON 보존, 게이트)은 유지하되 평가 중심으로 재편.

## §6 결정 포인트 (사용자와 함께 정할 것) [확정 초안]

1. 파일럿 목표 정의: "X일 안에 Y Elo/Elo-곡선" — 무엇을 측정하고 언제 멈출지.
2. 인간 리플레이 BC 워밍스타트 착수 여부 (데이터 실측: 구 MWL 수집분 614,304건; M-C 시즌 포함 — PA3 관측/행동 스키마로 변환 작업 필요).
3. 오프폴리시 전환의 검증 트랙: 파일럿에서 온폴리시 대비 A/B (Elo/시간).
4. 서치 증강(miku 스타일)을 목표로 둘지, 초기엔 보류할지.
5. 학습 목적지: 미니DC 단독 vs 클라우드 보조(스펙 금지 해제 여부).
