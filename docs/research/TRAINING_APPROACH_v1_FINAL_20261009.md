### 0.5.2 그들의 승리 공식 vs 우리

- **공통 승리 공식**: ① 자체 고속 시뮬 (miku: Rust 약 7,000 배틀/s/코어 [주장, 쇼다운 대비 650x], 8,192 병렬 / Jax: 순수 JAX GPU 병렬) → ② 대량 자기대전 PPO (1억-5억 경기) → ③ 테스트타임 서치 결합 (miku 1턴 동시수 내시 16월드, Jax pUCT depth4 32월드, **서치가 +100에서 150 Elo급** [Jax 본인 추정]) → ④ 소형 모델 (8.5-8.7M).
- **우리 위치**: 2×V100 32GB, 루프 실측 **32.50 games/s**(s5a 최종). 전체 엔진 용량은 2,579-2,689 games/s인데, 정책 추론과 PPO 업데이트가 끼면서 병목이 생기는 구조. 하드웨어 이론 성능(FP16)에서도 5090/H100 대비 열위.
- **결론**: 같은 방식(많은 경기)으로 정면 승부는 불가. 승부는 "**유효 성능 당 비용(Elo/시간, Elo/경기)**"과 "**그들이 못 하거나 안 하는 축**"에서 걸어야 한다.

### 0.5.3 검증 가능성에 대한 정직한 전제

- 세 봇 모두 비공개 + 래더 운영 제한적. **직접 대결로 "더 강함"을 증명하는 경로는 현재 없음**(Smogon 전시 챌린지 같은 이벤트성만).
- 따라서 "강함"의 검증 가능한 정의는: ① M-C(또는 OTS Bo3) 래더 Elo (miku 기록 1857, Nessie OTS Bo3 #1이 기준선), ② 공개 자산 상대 승률, ③ **동일 성능 도달에 필요한 경기 수(샘플 효율) 곡선** — 이건 우리가 정의해서 주장할 수 있는 새 지표다.

## 1. 현재 스택 최종 실측 (①의 답)

### 1.1 s5a 마감 상태

- **최종 학습 스피드: 32.50 games/s** (all-in, 2,048경기/이터레이션).
  - 분해: 수집 12.4s (165 games/s 상당) + 업데이트 42.2s. 이터레이션 54.6s.
  - 스케일: 일 2.8M 경기, 10M 경기 ≈ 3.6일, 30M ≈ 10.7일 (현 스피드).
- **rolling-slot 엔진 수정 (s5a W1)**: 커밋 `147247d`. 슬롯별 리셋 API 구현, 88 테스트 green, 오버슈트 50% → 1.7%. **A/B 32.501 vs 32.502 (flat, 노이즈 내) → 기본 미승격, opt-in 유지** (무승격 규율 세 번째 사례).
- **f16 관측 와이어 (s5a W2)**: 커밋 `deb3af0`. **no-go 판정.** 근거: 고정 뷰 41,954B 중 float 블록이 19,200B (45.8%). f16으로 절반으로 줄여도 뷰의 22.9% 절감뿐이고, 영향 단계 실측(native_observation 3.07s, parse_convert 0.88s, h2d 2.03s, all-in 101.9s 기준)에서 **낙관 모델로도 전체의 2.7%, 현실 밴드 1.0-1.4% → 선언된 ±2% 노이즈 이하**. 스키마 변경/패리티 게이트 리스크를 지불할 가치 없음. 보고서: `docs/perf/V5_F16_WIRE_POC.md`.
  - 함의: **관측 와이어(호스트↔GPU 전송)는 더 이상 유망한 레버가 아님.** f16+columnar 결합 설계는 미래 옵션으로 문서화만 됨.

### 1.2 병목 지도 (v4 아틀라스 + s5a 실측 갱신)

| 구간 | 현 실측 | 잠재 | 격차 원인 |
|---|---|---|---|
| 엔진 단독 | 2,579-2,689 g/s | — | (기준) |
| + 정책 추론 포함 수집 | 165 g/s 상당 | 수백-수천 | 배치 추론 부재, Python 관문 |
| + PPO 업데이트 | 32.5 g/s (all-in) | 수집과 오버랩 시 약 48-60 | 직렬 구조, 업데이트 42.2s 지배 |

- 업데이트는 GPU 포화(95%+) 상태로 42.2s. 순수 Python 오버헤드는 전체의 13-15% 수준.
- **남은 큰 레버 3개**: ① 직렬 구조(수집 중 GPU 유휴) ② 업데이트 자체 비용 ③ (중기) 배치 추론/시뮬 병렬화.

## 2. 비교 사례 총괄 (리서치 ①: 생태계)

### 2.1 하드웨어 상쇄의 실증: Nessie123

- **맥미니 + $120로 OTS Bo3 래더 #1.** 자기대전 37.5만 경기(우리 현재 페이스로 3.3시간 분량!). 수작업 팀풀 + OTS 근사 완전정보 학습 + 더블오라클/엔드게임 심화.
- 시사점: **포맷 선택 + 학습 설계가 컴퓨트를 이긴다**. Bo3/OTS처럼 정보 공개가 큰 포맷은 학습이 쉽고(완전정보 근사), 작은 자기대전으로도 정상에 갈 수 있음이 증명됨.

### 2.2 샘플 효율의 실증: Metamon

- 인간 리플레이(47.5만→100만+)로 IL → **오프라인 RL** → 자기대전 파인튜닝. 200M 모델로 인간 90-99 퍼센타일, **서치 없이**.
- 서버: 8×A5000 1대, 모델당 100만 스텝+. 데이터 전부 공개 (우리 786K+ 코퍼스와 직접 비교 가능한 선례).
- 시사점: **"인간 데이터 + 오프라인 RL"은 검증된 경로이고, 2026 커뮤니티 최상위 봇 3인방은 전원 이걸 안 쓴다(휴먼 데이터 0).** 우리의 코퍼스가 곧 차별화 재료.

### 2.3 방법론 공개의 실증: VGC-Bench (가장 가까운 벤치마크)

- 포켓몬 VGC 더블 연구 벤치 (arXiv 2506.10326, 8×A40, 70만 로그, 코드 공개).
- 결과: **BC 워밍스타트 + population 방법(BCSP/BCFP/BCDO)이 순정 자기대전보다 교차전 최강** (64팀 세팅: BCSP 0.878 vs SP 0.614). 단일 미러팀으로 인간 전문가에게도 승리 (선수 Aaron Traylor, 5-0 포함).
- 팀 수를 늘리면(1→64) 단일팀 성능은 떨어지고 일반화는 올라감, 착취 취약성도 커짐. **학습된 팀 빌딩/선출은 공개 연구에서 미개척으로 남겨둠.**
- 시사점: 우리 팀풀(1,137팀) 구조는 이 논문의 확장판. BC+population 조합의 근거가 도메인 안에서 실증돼 있음.

### 2.4 그 외 참조 자산

- **Chronoquazicalar** (2026-09, HF에 체크포인트 공개): JAX TPU v3-8, 초당 4,400+턴, 140M+턴, CFR+pUCT 내시 + Bayesian 세트 추론(509종). Jaxcalibur를 오픈 복제한 시도. → 우리 서치 구현 때 참조 소스.
- **FoulPlay**: DUCT MCTS depth약 5, 포지션별 세트 예측(사용률 통계 스크래핑). 싱글 OU지만 상대모델링 설계 참고.
- **PokéAgent Challenge (NeurIPS 2025)**: 상위 팀 전원 RL/서치 계열 (순수 LLM 아님). 스피드런 우승은 "서브골 → 스크립트 정책 → 증류+RL".
- **Ataraxos (Stratego, 2026)**: 16×H100 1주, 1.6억 경기, 인간 최강자 15-1-4 격파. **반복당 1 에폭 + 어드밴티지 필터링으로 업데이트 배치를 1/4 이하로 줄이고 wall-clock 2배 단축** — 우리 업데이트 병목(42.2s)에 직접 적용 가능한 기법.
- **CoG VGC AI Competition(학술)**: 쇼다운 아님(자체 Python 엔진). 2026 우승 SelfPlayFlat2026(배틀), Loblolly(챔피언십). 상위권 대부분 한국 참가자. → 참고: 별도 트랙으로 참가 가능성 존재 (§6.5).

## 3. 방법 공간 (리서치 ②: 표본효율/벽시계)

핵심 요약 (수치와 출처는 `research_sample_efficiency.md`):

1. **PPO 에폭**: 실무 밴드 3-10. 원논문 Atari 3 / MuJoCo 10 / Roboschool 15. VGC-Bench 10, Jaxpot 4, 우리 4. 2026 ωPPO: 반복 간 데이터 윈도우 재사용(ω=2-4)이 naive 에폭 증가보다 우수(ω=4에서 이득 대부분, ω=4 naive 증식은 붕괴). 다중에이전트는 비정상성 때문에 고재사용 주의 (MAPPO 15/10/5).
2. **오프폴리시/비동기**: IMPALA 제30배 처리량, V-trace ρ̄=c̄=1 클리핑. OpenAI Five staleness 목표 0-1 버전, 약 8 버전부터 감속. **"수집-업데이트 오버랩만으로 1.29×"** (우리 실측 54.6s → 42.2s, 본문 §9 권고 1순위). 계약(동결정책) 완화 필요.
3. **리그**: AlphaStar 이후 메인+익스플로이터+PFSP가 표준. 익스플로이터 제거 시 Elo 1824→1540, 순정 SP는 과거 상대 최소승률 46%(망각) vs PFSP+SP 71%. 우리 현재: current 0.5 + historical 0.5 (max 8 스냅샷) — 소형 PFSP로 확장 여지.
4. **서치 증강**: 완전정보 게임은 AZ/MZ 계열이 최강(샘플효율). VGC 같은 동시수+불완전정보는 2024-2026 실증이 (a) equilibrium 근사 트리서치 (b) R-NaD 계열+테스트시 서치로 수렴. 순수 모델프리 PPO는 이 클래스에서 약함. **우리 선택지: miku식 1턴 동시수 내시(저비용) → Jax식 pUCT 월드 서치(고비용)**.
5. **워밍스타트**: VGC-Bench에서 BC 초기화+population이 최강 [도메인 직증거]. AlphaStar 인간 init 어블레이션: 1020 → +Supervised KL 1400 → +Statistics 1540. RLPD: 오프라인 혼합 2.5× 개선. AlphaStar Unplugged: 오프라인만으로 SOTA급.
6. **소규모 성공 사례**: Ataraxos(16 GPU 1주, $8k), EfficientZero(4 GPU 7h), VGC-Bench(8×A40), MiniZero(4×1080Ti), Pluribus(블루프린트 12,400 코어아워). **소규모로 정상급 도달은 가능하다 — 단 "무엇을 학습할지/어떻게 검증할지"가 관건.**

| **G. 대외 검증 브리지** | 우리 정책을 Showdown M-C에 연결(추론 전용 어댑터) | 래더 실검증, 공개 대결 가능성, PR | 중-고. 프로토콜/관측 변환 엔지니어링 | **장기 (검증 목적, 별도 스코프)** |

## 5. 평가, 검증 재설계 (P0 상세)

현 문제: 평가가 100만 경기당 1회 → 학습 곡선이 안 보임.

제안:
1. **주기 평가**: 매 N 이터레이션(예: 30-60분마다) 소규모(2-4천 경기) 앵커 평가. 앵커 고정 세트(랜덤, 이전 스냅샷 대표 2-3개, 고정 봇) → Elo 추정 곡선.
2. **KPI**: Elo/시간 + Elo/경기(샘플 효율). 보고서마다 두 수치를 기록.
3. **기준선 (외부)**: ① 공개 자산(Metamon, FoulPlay)은 싱글이라 직접 비교 불가 → 우리는 "동일 방법 재현" 벤치로만 참조. ② M-C 래더는 브리지(G) 없이는 불가. ③ 당분간 정량 기준 = 자체 Elo 그리드 + 학습 곡선이라 명시.
4. **학습 곡선 파일럿**: 2-5M 경기 규모로 "경기 수 vs Elo" 곡선 먼저 확보 (어느 방법이든 비교 기준선).

## 6. 차별화 전략 (주인님 목표의 핵심)

정면 승부 회피 전제. 승부처 후보 5개 + 운영:

### 6.1 팀 축: 팀 프리뷰 + 팀풀 범용성 (미개척, 우리 최유력)
- 공개 웨이브 전원 미개척: Jax는 randbats라 팀빌딩 자체가 없음, miku는 **팀 편집이 약점**(10-07 트윗: "Rillaboom/Gambit만 넣음"), Nessie는 수작업 팀풀. VGC-Bench도 "학습된 팀 빌딩/선출"을 미개척으로 남김.
- 우리: 1,137팀 풀 자기대전 구조 + 팀 프리뷰 선출(6→4) 포함 가능. **"아무 팀이나 잡아도 강한 파일럿"은 현재 아무도 주장 못 하는 강점**이며, 우리 팀풀 벤치로 정량 검증 가능.

### 6.2 데이터 축: 인간 리플레이 (검증된 경로, 그들은 0)
- 786K+ 코퍼스 (단판 OTS 2,885건, Bo3 시트 ≈100% 보존 포함). Metamon/VGC-Bench가 검증한 경로. BC 워밍스타트(옵션 A)로 직결.

### 6.3 서치 축: 강도 + 엔진 충실도
- miku 16월드/1턴/무롤아웃, Jax 32월드/depth4 — **둘 다 아직 얕음**. 우리 엔진은 오라클 검증된 M-C 재현이므로 "모델 오차 적은 탐색"이라는 질적 차별화 + 월드 수/깊이 확장 여지.
- 주의: 서치는 추론 비용. 실서비스형(챌린지/래더)에선 지연 관리 필요.

### 6.4 정보 축: 상대 추론 보조헤드 + OTS/CTS 혼합
- Jax의 최대 기여 = **다음 행동 예측 보조헤드**. 우리도 이식 가능(관측 스키마에 상대 추론 여지 있음). Nessie의 OTS 편향(완전정보 근사)과 달리 OTS/CTS 혼합 학습으로 일반화 우위 노림.

### 6.5 아레나 선택 (무엇으로 "더 강함"을 주장할 것인가)
- **M-C CTS 래더**: miku와 같은 무대. 1857 기준선. 브리지(G) 없이는 불가. 최상위 난이도.
- **OTS Bo3**: Nessie의 무대. 정보 공개가 커서 우리 파이프라인(OTS 시트 보유)과 궁합. 학습 난이도 낮음. **차별화-우선 전략과 궁합 좋음.**
- **randbats**: Jax의 무대. 팀 축 차별화가 무효화되는 포맷 → 후순위.
- **CoG VGC AI Competition(학술)**: 자체 엔진, 참가 규모 작음(11팀), 한국 참가자 강세. 우리 엔진과 별개지만 "RL로 이 대회 우승"은 명확한 목표가 됨. 2027 주기 확인 필요.
- 권고: **본선 = M-C 계열(차별화 축 전부 적용 가능), 병행 후보 = OTS Bo3(빠른 정상 도전), 학술 트랙은 옵션.**

### 6.6 운영, 공개 정책 (선제 설계)
- 세 봇 모두 자기식별 + 래더 자제 + 챌린지 중심. Smogon이 봇 정책 성명 준비 중.
- 우리도 공개 범위(코드/가중치/방법론), 래더 사용 규율, 자기식별 정책을 선제 정의 → 리스크 관리 + 신뢰 자산.

## 7. 제안 실행 순서 (③으로 가는 길)

전제: 주인님이 RL 학습 중이므로, 각 단계의 "무엇을 왜 하는지"는 본 메모가 설명 가능하게 유지.

**Phase 0 (즉시, 0.5-1일): 평가 스파인 (P0)**
- 주기 평가 + Elo 곡선 도구. 소규모 파일럿 런(2-5M 경기)으로 "경기 수 vs Elo" 기준선 확보.

**Phase 1 (파일럿 배치, 각 1-2일): 즉효 레버 3종 병렬 검증**
1. **오버랩 파일럿** (B): 수집-업데이트 오버랩 → 1.29× 실측 확인. **계약 완화 승인 필요.**
2. **업데이트 슬림** (B-part): 어드밴티지 필터링 + 에폭 스윕(4 vs 6/10) 소규모 A/B.
3. **리그 확장** (C): 스냅샷 풀 8 → 20-50 + PFSP 가중. config 변경 수준.

**Phase 2 (1-2일): BC 워밍스타트 파일럿 (A)**
- 리플레이 파싱 → BC 사전학습(소형) → 같은 예산으로 RL 파인튜닝 vs 스크래치. Elo 곡선 비교.

**Phase 3 (1-3일): 서치 파일럿 (D)**
- 1단계: miku식 1턴 내시 서치 래퍼 (추론 전용, 학습 불변). Elo 델타 + 지연 측정.
- 2단계: Jax식 pUCT 월드 서치 확장 (선택).

**Phase 4: 본학습 설계 확정**
- Phase 1-3 결과로 조합 확정 (예: 워밍스타트 + 오버랩 + 슬림 업데이트 + 확장 리그 + 서치). 
- 타깃 재정의: **100M 경기 → "10-30M 경기 내 X Elo"** (개선 후 스피드라면 수일-2주 규모). KPI = Elo/시간, Elo/경기.

**Track Y (병행 가능): 정보/보조헤드 (6.4)** — Phase 1 후.
**Track G (장기): Showdown 브리지** — 대외 검증이 필요해질 때 별도 스코프.
